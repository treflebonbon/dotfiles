# Managed Chrome の所有権管理を共通化し、停止未確認時は明示復旧する

Managed Playwright Chrome と Managed Dogfood Chrome は共有の所有者記録を Bash と JavaScript で別々に管理し、更新・解放の手順が異なる。Playwright の通常終了では Chrome の停止確認まで記録を保持する一方、起動失敗や Dogfood の cleanup 失敗では確認できなくても解放する経路がある。同時起動禁止を維持するため、記録の操作だけでなく、停止確認と解放の関係も共通の契約にする。

## Decision

1. [ADR-0038](0038-keep-wsl2-browser-free.md) の用途別 browser identity と同時起動禁止を維持する。所有権の予約・取得・競合判定・更新・解放を一つの module に集約する。
2. Chrome の起動・停止と実体の照合、profile 管理、Playwright の CLI session・Dashboard、Dogfood の run・拡張機能の処理は用途別の担当に残す。用途別の担当が実体の状態を確認し、共通部分が所有権を解放できる条件を管理する。
3. 起動を試みた後や終了処理で Chrome の停止を確認できない場合は、所有権を保持して別用途の起動を拒否する。所有者と復旧手順を表示し、明示的な復旧操作で再確認する。通常の起動時に残存する所有権を自動回収する方式は採用しない。
4. 明示的な復旧操作は、対象が停止済みであることを確認して所有権を解放する操作とする。Chrome の終了要求、強制終了、profile の変更・削除は行わない。動作中または確認不能なら記録を保持し、対象に応じた終了・再確認の手順を示す。
5. 新しい仕組みへの切替は、既存の Managed Chrome・CLI session・Dashboard を終了してから行う。起動中の状態の引継ぎと新旧処理の混在には対応しない。残存する旧記録を空き状態とみなしたり、自動削除したりせず、復旧手順を示す。

## Interface

既存の Node runtime を使う共通 CLI `managed-chrome-owner` を、browser 用の PowerShell script と同じ Nix package に同梱する。Bash wrapper と Dogfood の両方がこの入口を使い、状態ディレクトリの解決、記録形式、排他制御、所有権の照合を直接実装しない。人間向けには `status` と `recover` を公開する。用途別の実体照合処理も同じ package から呼び出せるようにし、Dogfood runner の異常終了後でも復旧できる構成とする。

呼出側には予約、起動結果の確定、利用終了の通知を提供する。操作は取得ごとに識別された所有権を対象とし、同じ session 名・run 名を再利用しても、古い要求が新しい所有権を変更・解放しない。Playwright の CLI session と Dashboard の共存・最後の利用者の判定は、既存の用途別担当が維持する。

新しい記録では形式の版、取得ごとの識別子、起動予約の状態、起動元の識別情報、Windows の Chrome の識別情報を区別する。共通部分が Playwright 固有の `runtime.lock` の場所と規則を重複して知る方式は採用せず、共通の予約状態と用途別の実体照合を使う。旧形式を起動中のまま変換する互換処理は持たない。

## Release conditions

- Chrome 起動前から終了確認まで所有権を保持する。起動前の中止、起動失敗、通常終了、明示復旧のどの経路でも、後から Chrome を起動し得る処理が残っている間は解放しない。
- 起動中の予約を、Chrome がまだ見つからないことだけで復旧・解放しない。起動処理の完了を確認できない場合も保持する。Linux の呼出元 process と Windows の Chrome は別の実体として扱い、片方の PID の不在だけで停止済みと判定しない。
- 実体照合は「動作中」「停止済み」「確認不能」を区別する。PowerShell 呼出し全体だけでなく内部の process・port 照会の失敗も確認不能として扱う。不正・未知の記録、実体の不一致を停止済みに読み替えない。確認中に所有権が変わった場合は、以前の確認結果で新しい所有権を解放しない。
- 記録の照合・更新・解放は共通の排他制御下で行い、書込み途中の記録を正常な状態として公開しない。競合時は既存の所有者と終了手順を示して起動を拒否する。
- 一時 profile の削除失敗と Chrome の停止失敗を分ける。Chrome と起動処理の停止を確認できた場合は所有権を解放できるが、profile の後始末に失敗した事実は別途報告する。`recover` は profile の後始末を行わない。

## Considered Options

- 同時利用を可能にする案は、今回の目的である排他処理の共通化から利用ルールの変更へ範囲が広がるため採用しない。
- Chrome の起動から終了までを共通化する案は、profile の保持期間や Dashboard などの用途差を共通部分へ持ち込むため採用しない。
- 次回起動時に停止済みの所有権を自動回収する案は、利用者の手間を減らせる一方、通常起動に回復処理の判断が加わるため採用しない。
- 復旧操作で対象の Chrome の正常終了も試みる案は、所有権の回復と browser の終了処理を分けるため採用しない。
- 起動中の状態を引き継ぐ案は、停止時間を避けられる一方、現在の用途別に意味が異なる記録と新旧の処理を混在させる必要があるため採用しない。

## Consequences

終了確認に失敗した後は、明示的な復旧が済むまで新しい用途を開始できない。Dogfood の cleanup 失敗時に常に所有者記録を消す既存テストは、この解放条件に合わせて見直す必要がある。起動失敗経路も同じ条件で検証する。

配備には Nix package とローカル Dogfood skill の両方の更新が必要になる。対応する版を揃えてから利用を再開し、同じ排他状態を参照できない構成や必要な共通 CLI がない場合は起動を拒否する。既存の配布所有権、chezmoi の実行順序・変更検知、非 WSL の browser 経路は維持する。distribution 横断の所有権共有は今回追加しない。

実装時は一時状態ディレクトリで両 caller の同時取得、起動途中の復旧、古い要求による解放、終了・照会失敗後の保持、停止確認後の復旧、旧記録の拒否を検証する。用途別の既存テストに加え、ADR-0031 / ADR-0038 に基づく WSL2 実機での通常操作・Dogfood・Dashboard/annotation・排他競合の確認を完了条件とする。

本 ADR は所有権管理の共通化と復旧方針を定める。[ADR-0031](0031-managed-playwright-chrome-on-wsl2.md) の profile・認証・モード・CLI session・Dashboard の契約と、ADR-0038 の browser-free 境界は引き続き維持する。
