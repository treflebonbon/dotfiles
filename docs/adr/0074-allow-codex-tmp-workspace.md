# Codex の /tmp をスキルの一時作業に利用可能にする

Herdr の通常起動で Codex 0.162.1 を検証すると、管理 profile の `":slash_tmp" = "deny"` により、ホストに存在する `/tmp` の通常ファイルが sandbox 内では見えなかった。worktree 内と、そのセッションの `$TMPDIR` 配下の通常ファイルは読み取れた。

ユーザーは「スキルなどで `/tmp` は一時作業場所に利用されることが多い」ことを理由に、任意の `/tmp/...` をそのパスのまま参照できることを選択した。その後、一時ファイルの読み書きを許可し、Codex の共通管理設定へ適用する方針を選択した。

## 決定済みの方針

- `/tmp` の読み書きを許可し、スキルによる一時ファイルの作成・再読込み・更新・後片付けに対応する。OS の所有者・アクセス権と、実際の削除操作に対する既存の承認規則に従う。
- 共通の `dotfiles-secure` profile に適用し、管理設定を利用する Herdr の通常起動・通常の Codex CLI・アプリで方針を揃える。既存の管理設定同期を利用する。
- dotenv・鍵・credential など、既存の機密ファイル名の拒否規則を `/tmp` 配下にも適用する。既存の許可 root に対する拒否規則も維持する。
- raw `codex-worktree` の外側の隔離を維持する。raw で利用するのは隔離内の `/tmp` であり、ホストの `/tmp` は共有しない。[ADR-0044](0044-runtime-owned-worktree-entry-and-codex-activation.md) の秘密分離の境界を維持する。

## 機密ファイル名の扱い

現行の dotenv・鍵・credential の拒否規則は、`:workspace_roots`、`~/.local/bin`、`~/.config/git`、`~/.config/gh` に設定されており、一般の `/tmp` 配下には自動では適用されない。ユーザーは、同じ拒否規則を `/tmp` 配下にも適用する方針を選択した。

これにより通常の一時作業と既知の機密ファイル名の保護を両立する。スキルが `/tmp` に作る鍵や dotenv の検証用 fixture も拒否対象になる。名前にかかわらず `/tmp` 内のファイルを許可する案は採用しない。ファイル名の拒否は内容による機密判定ではないため、異なる名前で保存された機密データまでは識別しない。

2026-10-15 の `grill-with-docs` でユーザーが設計全体に合意し、本方針を採用した。設計確定時点では設定変更・配備は行っていない。

## 実装上の判断

`dotfiles-secure` の `:slash_tmp` を `write` にし、共通の拒否パターンを明示的な `/tmp` の table にも展開する。`/tmp` の `.env` だけは、存在しない `/tmp/.env` に一時的な mount target を作らない glob にする。既存と同じ `glob_scan_max_depth = 4` を使用するため、拒否は実行開始時に見つかった深さ 4 までのファイルが対象であり、将来作られるファイルや別名の秘密までを保証しない。

Linux の Codex 0.162.1 では `/tmp/systemd-private-*` などの読めないディレクトリにより、機密ファイル名の ripgrep 走査が終了コード 2 となり、公開ファイルへの操作も起動前に失敗した。深さを限定したパターンでも再現したため、既存の Linux package のパッチ経路に修正を加える。終了コード 2 の場合は既存の内部 walker で再走査し、読み取り不可のディレクトリを丸ごと拒否対象にする。その他の走査エラーは引き続き起動失敗とし、拒否規則を省略しない。

設定の同期時は明示的に管理する `/tmp` の table を古い worktree の展開結果と区別し、利用者が追加した拒否ルールを保持する。実 sandbox の HOME fixture は書込み可能な `/tmp` の外に置き、通常の HOME と同じ権限境界で検証する。

## 検証方針

管理設定の期待値と実 Codex sandbox の回帰検証を更新し、`$TMPDIR` 外の `/tmp` にある公開ダミーファイルの読み書き、一時ファイルの作成・更新・後片付けを確認する。`/tmp` 配下の dotenv・鍵・credential の拒否をダミー値で検証する。既存の worktree 内の機密拒否と `.envrc`・`.env.example` の許可を維持する。

Herdr の通常起動で実効権限と操作結果を照合する。raw の実隔離検証では、ホスト `/tmp` のダミーファイルが見えず、隔離内の一時領域を利用できることを確認する。設定の検証では秘密値を使用しない。

## 影響

通常起動の Codex は、機密ファイル名の拒否対象を除き、同じユーザーがアクセスできる他セッションや他ツールの `/tmp` の一時ファイルも利用可能になる。セッションごとの `$TMPDIR` のみを許可していた範囲から、スキルが利用する一般の `/tmp` へ範囲を広げる。

未 merge の task worktree から `chezmoi apply` は実行せず、受入後に live source から配備する。起動済みセッションへの反映は未検証で、新しい Codex セッションでの確認を前提にする。
