# ui-grill-with-docs の実行評価

2026-09-10。`empirical-prompt-tuning` で、1枚のHTMLによるラウンド質問シートを実際に生成する能力を評価した。

## 評価契約

対象は [SKILL.md](../../local-skills/ui-grill-with-docs/SKILL.md) と同梱の [round.html](../../local-skills/ui-grill-with-docs/assets/round.html)。既に実施したテンプレートのブラウザ検証とは別に、会話履歴を引き継がない実行者がskillを読み、課題に適合したHTMLを作れるかを見る。

Iter 0では、descriptionが述べる「各ラウンドの全質問・比較モック・回答欄を1枚のHTMLにまとめ、Markdownでコピーする」と、本文・テンプレートの対象範囲が一致した。ここでの修正はない。

[scenarios.json](../../local-skills/ui-grill-with-docs/evals/scenarios.json) に通常・継続・未使用例の3シナリオと各6項目を事前固定した。各項目は○=1、partial=0.5、×=0。成功判定はcritical指定した項目がすべて○の場合のみ○とする。実行後に項目やcritical指定を変えない。[previous-round.json](../../local-skills/ui-grill-with-docs/evals/previous-round.json) は継続ケースの入力である。

| ケース   | 課題                                           | 主な判断境界                                                                           |
| -------- | ---------------------------------------------- | -------------------------------------------------------------------------------------- |
| A: 通常  | 備品申請画面のレイアウト、ボタン文言、表示項目 | 3問を集約し、項目選択に依存する表示順は先に聞かない                                    |
| B: 継続  | 表表示と2項目が確定し、ボタン文言だけ未回答    | 同じHTMLを次ラウンドへ更新し、未回答の文言と新たに判断可能な表示順を質問する           |
| 未使用例 | 通知画面の名称、種別、本文の具体例             | 文章だけの質問にもHTMLを使い、`</script>` 等を安全に扱い、確定済みの配置を再質問しない |

実行者は評価ごとに新規作成し、別々の隔離fixtureとread-onlyのskill snapshotを渡した。人間向けの応答は `response.md` に書かせ、実際のユーザーへ質問したり回答を創作して先へ進めたりせず、現在ラウンドの回答待ちで停止する。実行者は成果物と自己報告を残す。親セッションはそれを独立に読み、生成HTMLをブラウザで操作して採点する。

`tool_uses` と `duration_ms` は現在のcollaboration APIがnative metadataを返さないため、全実行で未取得。実行者の自己申告、時刻差、出力文字数、0などでは代用しない。再試行は「同じ判断をやり直した回数」の自己報告値を記録する。

Bの自己報告は全項目○だったが、親の照合でcritical項目1をpartialと判定した。入力r1で未回答だった「申請する／依頼を送る」を、r2で「備品を申請する／申請を作成」に置換していた。「ボタン文言」という話題は保っても、元の未解決質問の候補を維持していない。項目1の「未回答のボタン文言を質問する」という事前の基準に照らして採点したもので、評価項目を追加したものではない。その他の固定項目とブラウザ操作は両ケースとも通過した。

- Cause: 本文の一般的な「stable ID」と、末尾の「未回答を次シートへ含める」が離れており、次ラウンドで何を維持するかが具体化されていなかった。

裁量補完のうち、Aの一覧対象を自分の申請とみなす前提と、Bの列順推奨・例示列は記録した。Bの文言変更は許容される裁量として採用しない。

## 修正

固定したBのcritical項目1「未回答のボタン文言を質問する」を満たすため、質問繰越しの段落へ4行を追加した。未回答のquestion ID・prompt・choice IDs・choice labelsを維持し、ラウンドIDの変更と未解決質問の意味の変更を区別する。人間のフィードバックが変更を求める場合は更新でき、新提案は既存候補と分ける。

## 未使用例

修正版を、これまで実行者へ渡していない通知設定のケースで実行した。配置の判断は確定済みで、質問は文言・受信種別・本文の具体例だけである。

| ケース   | 成功 | 達成率     | tool_uses | duration_ms | 再試行（自己申告） | 弱いphase |
| -------- | ---- | ---------- | --------- | ----------- | ------------------ | --------- |
| 通知設定 | ○    | 6/6 = 100% | 未取得    | 未取得      | 1                  | なし      |

3問は同じHTMLにあり、不要な比較モックは作成されなかった。質問文に `</script>` と `<更新>` を含めても埋め込みJSONは壊れず、ブラウザで自由記述とMarkdown出力、復元、コピー・保存の失敗時の動作まで通過した。直近のA/B平均100%からの低下は0ポイントで、この未使用例では15ポイント以上の低下は観測していない。

Trace all OK、Unclear points none。自己申告のRetries 1は、実際の視覚モックではない汎用 `visual-*` 参照を自分の静的検査が誤判定したため、検査条件を直した回数だった。質問・推奨・HTMLの実装判断は変更していない。原報告の1を保持し、指示の曖昧さによる設計判断のやり直しとは区別する。

## Failure pattern ledger

- **未回答質問の再生成による候補のすり替わり**
  - Example: r1の「申請する／依頼を送る」が、回答前に「備品を申請する／申請を作成」へ変わる。
  - General Fix Rule: 未解決判断の繰越し位置で、維持すべき質問の識別子と内容を明示する。
  - Seen in: iter 1 B（IDのみ）、iter 2 B（IDと候補の意味）。
  - 既存指示が防げなかった理由: 「stable ID」は質問定義時の一般則として読まれ、次ラウンドの再生成処理まで適用されなかった。繰越し段落へ規則を併置した。

## 結論と限界

4反復×2ケースと未使用例1件、計9回を独立した実行者で実行した。発見した問題は、未回答の質問候補を次ラウンドで再生成してしまうことだった。繰越し位置への4行追加後、通常・継続ケースは2回連続で6/6、未使用例も6/6だった。

終了判定は **qualitative plateau; quantitative convergence unverified**。`tool_uses` と `duration_ms` がないため、これらのroundをstrict convergenceの成立に数えない。今回は明示的な **resource cutoff** とする。定量収束の確認にはnative metadataを提供する環境で同じ評価を行う必要があり、同じ条件の実行をこの環境で増やしても欠けた測定値は埋まらない。

固定した有限の課題での結果であり、一般的な成功率や人間の回答負荷の改善率を推定しない。実行者には要件チェックリストも渡している。実ユーザーとの長い往復、ブラウザを閉じた後の別セッション再開、用語集・ADRの品質全般、`file://` の権限はこの評価の対象外である。ブラウザ検証はローカルHTTPの生成物で行い、外部ネットワークへのリクエストはなかった。

[results.json](../../local-skills/ui-grill-with-docs/evals/results.json) に各実行の採点、自己申告値、成果物SHA-256、原自己報告とHTMLの場所を残した。[frozen-manifest.json](../../local-skills/ui-grill-with-docs/evals/frozen-manifest.json) は修正前後のtargetと、固定した評価定義のSHA-256を持つ。評価定義のJSONはdispatch後にformatだけ行い、各scenarioの値とcritical指定が配布済みsnapshotと一致することを検証した。

HTML・原自己報告・ブラウザ検査の詳細はworktreeの `tmp/empirical-ui-grill/` にあり、Git対象外の一時成果物である。再評価では固定シナリオから新しい隔離fixtureを用意し、未実施の実行者へその時点のtarget snapshotを渡す。Bの入力には `previous-round.json` をテンプレートへ埋め込み、所有する `tmp/ui-grill-request.html` と別セッションの成果物を準備する。

修正後、`grilling uses` と `ui grill` のリポジトリ契約テスト2件、変更文書のformatter、差分の空白検査も通過した。live skillへの配備は行っていない。
