## Q2 — 比較手順の適用範囲（合意済み）

確認済み: 現SKILLの純粋性段落は入力snapshot比較と同入力の結果比較を求めるが、初回直後と再呼出し後のそれぞれに入力比較を置く順序、および初回結果の別snapshotを明示しない。v10 Eはこの順序を要求しており、01/04は初回結果snapshotはあるが初回直後の入力比較がない。

- 採用: 純粋な遷移モデルに共通する比較手順として本文の既存段落へ短い具体例を置く。比較の順序を必須とし、関数名・検査ライブラリ・snapshot/equalityは対象表現と既存プロジェクトに合わせる。具体例の通常データという前提を明記し、Eの状態表現制限は一般アプリへ広げない。
- 代案: E型の通常データモデルだけに具体例と明示的な比較順序を適用し、その他は現行の抽象的な指示を保つ。適用範囲は狭いが、同様の抜けが他の純粋モデルで残り得る。

実装例のclone/equalityが状態・返却値の意味を保存することが前提。opaque等で標準cloneが不適合なら意味を検査できる既存の方法へ置換し、空の外形比較で成功とはしない。初回結果を再呼出し前にsnapshot、各呼出し直後に入力比較、最後に初回結果の保持と同入力の結果一致を照合する。state以外の入力への新たな検査要件はこの案に追加しない。

## Q3 — 設計全体（合意済み）

### 変更内容

対象は `local-skills/mvp-mediator-architecture/SKILL.md` の「純粋な遷移」段落とその直近の短い具体例。既存の抽象的な比較説明を次の順序へ具体化し、離れた節へ同じ規則を重複追加しない。関数名やライブラリは固定しない。

```js
const before = snapshot(state);
const first = transition(state, event);
assertEqual(state, before);
const firstBefore = snapshot(first);
const second = transition(state, event);
assertEqual(state, before);
assertEqual(first, firstBefore);
assertEqual(second, firstBefore);
```

これは比較順序の例。snapshotは状態・返却値の意味を保持した独立の記録、assertEqualはその意味に合う等値比較を表す。通常データには標準の複製・深い比較を使える。opaqueや独自表現では既存の意味を検査できる方法へ置換する。意味のある比較を用意できない場合は純粋性確認済みとせず、未確認の範囲と必要な確認方法を記録する。汎用snapshotライブラリや独自inspect APIの追加は要求しない。

比較対象は検査対象遷移の入力stateと全返却値。各呼出し直後の入力比較、再呼出し前の初回結果snapshot、初回結果の保持と同入力の結果一致をassertする。eventへの新たな不変検査や全遷移網羅は追加しない。effectsを返すモデルではeffectsも返却値に含めて比較する。純粋なモデルの既存適用範囲を保ち、実アプリのstore/Atom/Effect等へ通常データ表現を強制しない。Bの提案のみには実行モデルを追加しない。

状態分類と根拠表の改善は対象外。通常経路の独立性、表示導出、責務分担、未実行の区別など既存要件は保持する。
