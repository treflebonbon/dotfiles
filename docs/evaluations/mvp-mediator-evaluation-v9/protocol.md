## 維持する条件と比較の制限

## 実装Contract

1. 状態表にモデル内の表現と本実装の情報源を別欄で示す。全保持フィールドの目的・所有者・4区分を維持する。本実装の情報源は既存機構の値、追加する所有者、または未確認＋具体的な確認対象で説明完了とする。未確認を実装検証済みと扱わない。検証専用の補助は本実装で不要と説明できればよく、実装では抽象モデル専用欄を省略できる。
2. 実行検証済みと主張する観測時点ごとに根拠表の行を分け、各時点の具体値・期待値・assertion・実行結果を結び付ける。同じ時点の複数値はまとめられ、全assertionの転記は不要。共通コマンド・出力は参照で共有できる。
3. 根拠表・要件別達成欄と正確な重複の許容、表外を含む主張の正確さを維持する。必要な検査の不足は追加・実行で埋める。提案のみは具体的な確認案と未実行を記す。通常経路の分離、純粋性、表示導出、最終編集後の照合、事前整理の推奨、既存の適用範囲と責務分担を維持する。
4. 改善範囲はskill単体。既存表と隣接する完了条件を置き換え、別のチェックリストや報告生成器を追加しない。公開CLIのinit/prepareで新本文とv2〜v9契約を固定・配布する版登録と対応検査だけを更新し、runtime・採点ロジック・配布テンプレートを変更しない。

検証境界は合意済み公開CLI fixture。専用Batsで新版固定・配布のred→green、型確認、skill形式検証、全体テスト、Standards/Specレビューを行う。fixtureは行動改善の証明には使わない。
