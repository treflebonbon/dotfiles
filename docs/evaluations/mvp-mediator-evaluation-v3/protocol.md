[v2契約](../mvp-mediator-evaluation-v2/protocol.md)（SHA-256 `19c48ebb1c35a7aa5d011c3b280a5451ed5cdbc8dd56ddba8607dceff790fbae`）を基礎とし、以下の差分だけを優先する。v2の対象本文・参照・課題・API・6基準・critical指定・C1〜C4・実行上限・metadata規則は維持する。背景は[親評価者の監査補足](../mvp-mediator-evaluation-v2/run-20260922-01/parent-audit-addendum.md)。旧runへ遡及適用せず、新規runの開始記録へ両契約のpath/hashと実行入口の版を固定する。

## 1. 実行者へケース別出力の要件を渡す

v2手順2の配布テンプレートで、「検査名は実行したコードに存在する名前を使い、検査範囲は実際のassertionに合わせてください。」の直後に次を挿入する。他課題・親の採点規則・過去結果は配布しない。

```text
  実行モデルを作る課題では、実行した各名前付きケースの名前と成功・失敗を検査コマンドの結果に出力してください。既存runnerの出力でも構いません。成功はそのケースのassertion完了後にだけ記録し、失敗した検査は非0終了にしてください。メモには実出力を対応付け、未実行ケースを成功と記録しないでください。
```

配布承認前に親が、保存されたpromptにこの要件と担当課題の全基準があることを確認する。欠落時はdispatchを保留する。Bは提案確認のままで、モデルやケース別実行出力を求めない。

C2の判定では、配布した要件、ケースを実行するコード、toolの実出力を対応付ける。親用契約にしかない要件を対象スキルの適用漏れへ帰属させない。配布漏れが実行後に判明した場合は親側の契約伝達不良として記録し、その実行をclearにしない。親が成果物を補修して合格へ変えることはしない。

## 2. 監査確定時の未解決失敗だけを再発停止へ数える

v2手順5の「同一失敗パターン」を、**各実行の親監査確定時に残る、入力・成果物・監査証拠・必須条件の未達**と定義する。同じ未達が独立した2実行で再発したら、開始済み実行を回収し、新規dispatchを止める。監査確定前の次回dispatchは行わず、実行は直列とする。

| 監査時の状態 | 再発停止・clearへの扱い |
| --- | --- |
| 同じ実行内で復帰し、必要な入力・成果物・検査・証拠が揃った機械的／環境エラー | エラーと復帰の証拠を保存するが、停止パターン・clear阻害項目に含めない |
| 読取り不能、成果物未作成、必要な検査失敗、監査証拠不足が残る | 該当する未達として停止パターンへ数える。証拠不足はunknownを保持する |
| 禁止入力の混入・指定外変更・承認境界違反が起きた | 後から正常に完了しても復帰済みとはしない。起きた違反を監査へ残し、clearにしない |
| 明示必須のツール・手順を代替手段で省略した | 同じ目的を達成しても必須条件の未達として数える |

復帰判定には失敗のcall/result、代替または再実行のcall/result、同じ目的・対象について必要な結果を得た根拠を記録する。終了コードだけで判定せず、pipeline途中の失敗や返却内容も確認する。機械的リトライ回数はv2の定義を維持し、並列に実行した代替手段を「失敗後のリトライ」と数えない。

`find`が未提供でも、任意の探索を`rg`で完了し必要な証拠を揃えた場合は復帰済みである。これだけでは停止せずclearも妨げない。一方、Eの通常経路分離やメモと実検査の一致が未達なら、別の未解決失敗として扱う。

親監査の`failure_patterns`と`issues`には上記の未解決条件だけを入れる。復帰済みエラーは参照先の環境記録に残し、判定理由からリンクする。判定根拠を残したまま、復帰済みエラーと未解決条件を混ぜない。入力監査ではpath/hashだけでなく、検索・Git差分を含む返却内容も照合してから次回起動可否を確定する。

1組のclearは従来どおりE/B/Sすべてのvalid・6項目全○・C1〜C4全passを要する。新しい不明点・既知の適用漏れは監査確定時の未解決事項で判定する。復帰済みエラーを除外しても、残る未達を相殺しない。

## 3. 専用入口へ接続するときの受入条件

現在の[専用CLI](../../../scripts/mvp-evaluation.py)はv2のpath/hashとテンプレートを固定しているため、そのままではv3を実行できない。接続時は新規runの固定入力と配布テンプレートをv3に対応させ、親監査の分類を使う。既存run・v2契約・元のaudit/state/resultsは保持する。汎用の採点自動化は追加しない。

モデル通信なしのfixtureで、次を確認してから新規本評価を開始する。

- 生成promptに手順1の要件が入り、担当課題以外の本文が混入しない。
- 復帰済みエラーを2実行へ記録しても、それだけで停止・clear不成立にならない。
- 同じ未解決失敗が2実行で再発すると次回prepareを拒否する。
- 未監査、証拠変更、入力無効、置換・dispatch上限、Lの投入条件に対する既存ゲートが維持される。

契約作成とCLI接続・本評価は別の作業である。本書の追加だけでv3の実行や収束を確認したとは扱わない。
