# S: held-out search UI

## 責務とイベント

| 所有者 | 状態・責務 | イベント |
| --- | --- | --- |
| 既存 Query binding / 実行層 | 各 request の `pending` / `result` / `error`、検索の実行、best-effort cancellation | `search(text)`、成功・失敗の完了通知 |
| `SearchResultAcceptanceMediator` | 追加状態 `latestRequestId`、表示への結果採用、`view.pending/results/error` の遷移 | 検索要求、binding からの完了通知 |
| Passive View | 表示、検索要求の通知 | `search(text)` |
| `HelpTooltip` | `open` のみ | `toggle()` |

Query の通常の実行と各要求の pending/result は既存 binding を再利用する。追加する裁定状態は `latestRequestId` だけであり、文字列比較ではなく request identity と完了通知の `id` を照合する。結果採用の UI 所有者は `SearchResultAcceptanceMediator` の一つだけである。

| 前状態 | イベント | 後状態 | 資源所有者 | 実行効果 |
| --- | --- | --- | --- | --- |
| idle | `search(text)` | latest request が pending | binding | Query を既存経路で開始 |
| latest pending | latest の成功・失敗 | 表示へ成功・失敗を採用 | binding | binding の各 request 状態を完了 |
| newer pending | 古い成功・失敗 | newer pending を維持 | binding | 古い request 自体は完了、表示は変更しない |
| 任意 | tooltip toggle | 検索表示は不変 | Tooltip | tooltip のみ開閉 |

cancellation は binding の既存機構に委ね、サーバー処理の巻き戻しを意味しない。Effect、Atom、自作 scheduler、Promise は導入しない。

## 6 基準

| 基準 | 判定 | 理由 |
| --- | --- | --- |
| 1 | ○ | `latestRequestId` と completion `id` を照合し、同一 text の再要求も別 id と assertion で確認する。 |
| 2 | ○ | 古い成功・失敗とも新しい `pending/results` を変更できず、現在の失敗・成功が適用される assertion を実行する。 |
| 3 | ○ | binding が各 request の pending/result/error と実行を持ち、Mediator の追加状態は採用用 id のみ。 |
| 4 | ○ | Effect/Atom/custom scheduler/Promise を追加せず、cancellation の server rollback も主張しない。 |
| 5 | ○ | `HelpTooltip.open` は局所状態で、結果採用者は `SearchResultAcceptanceMediator` と明記する。 |
| 6 | ○ | 本メモとモデルの責務・遷移・実行済み assertion を一致させ、runtime integration 非対象を明記する。 |
