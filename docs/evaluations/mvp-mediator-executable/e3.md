# E3 実行メモ

## 責務マップ

共通親 Mediator は、recording と calibration の排他、最新の開始意図、停止・解放・再取得の順序、失敗時の明示的再試行、完了 ID の採用を裁定する。子フローは開始要求と局所表示だけを持つ。profile editor は独立し、`profile` はこのモデルの状態も effect も変えない。Effect 実行境界は出力した `acquire` / `stop` / `release` を実行し、型付きエラー、defect、中断、資源寿命を扱って ID 付き完了を返す。純粋モデルは I/O、scheduler、runtime を持たない。

## 実際の検証と限界

実行済み: `node docs/evaluations/mvp-mediator-executable/e3.mjs` は `e3 self-check: passed` で終了した。assertion は取得中の意図往復、停止後の同一所有者への復帰、停止・解放の失敗と段階別 retry、取得失敗、古い ID、profile の無影響を再生する。

未実行: 実際の Effect runtime、React 接続、デバイス API、型付きエラー／defect／中断／Scope の寿命管理はこの抽象モデルの対象外である。実装時は Effect 境界が effect を一回だけ実行し、同じ ID の完了を親へ返すことを結合テストで確認する。

## 凍結基準

| 基準 | 判定 | 理由 |
| --- | --- | --- |
| 1 | ○ | `acquiring`、`stopping`、`releasing`、`blocked` で desired だけを更新し、既存 stage の I/O と ID を維持する。取得完了後だけ latest intent と owner を比較する。 |
| 2 | ○ | stop 成功は release を発行し、release 成功後だけ acquire を発行する。stop/release 失敗は blocked とし、retry は失敗した stage だけを新 ID で再実行する。 |
| 3 | ○ | `nextId` は各 stage/retry で増加し、ID 不一致の完了は同じ state と空 effects を返す。 |
| 4 | ○ | モデルは effect command のみを出力し、実行・中断・寿命・エラー分類を Effect 境界に残す。 |
| 5 | ○ | `profile` は同じ state と空 effects を返す。子フローの局所状態はモデルに含めない。 |
| 6 | ○ | 実装、上記の実行済み assertion、責務と未実行範囲の記録が一致する。 |

## 不明点と判断

| 項目 | 内容 |
| --- | --- |
| Unclear Issue | `blocked` 中の `operationId` が「失敗済み ID」か「pending ID」か。 |
| Cause | API は pending execution ID と定義し、失敗後に実行中の処理はない。 |
| General Fix Rule | pending でない ID は `null` にし、失敗 stage は内部状態として保持して retry 時に新 ID を発行する。 |

任意判断: acquisition failure 時は、次回 start を独立した新要求にするため desired を `null` に戻す。停止開始後は desired が旧 owner に戻っても stop/release を完了し、その後に最新 desired を acquire する。再試行回数: 実行自己検証では stop と release を各 1 回、合計 2 回。実装は retry 回数を制限しない。
