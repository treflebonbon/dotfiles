# E2 実行モデルメモ

## 責務と成果物

| 担当 | 成果物・責務 |
| --- | --- |
| 共通親 Mediator | `e2.mjs` の `transition`。録音と較正の排他、最新 intent、停止・解放・再試行の裁定をする。 |
| 子フロー | 録音・較正それぞれのローカル UI。親へ `start` を通知するだけで、相手を直接操作しない。 |
| プロフィール編集 | 独立したローカルフロー。`profile` はデバイス状態も effect も変えない。 |
| Effect 実行境界 | `acquire` / `stop` / `release` コマンドを実行し、型付きエラー、defect、中断、寿命を扱って `ok` / `fail` を返す。 |

モデルは I/O、scheduler、Effect runtime を持たず、コマンドを出力するだけである。

## 固定基準の判定

| 基準 | 判定 | 理由 |
| --- | --- | --- |
| 1 | ○ | acquiring/stopping/releasing/blocked の `start` は desired のみ更新し、既存 operation ID と I/O を維持する。元の target へ戻しても重複発行しない。 |
| 2 | ○ | stop 成功後だけ release を発行し、release 成功後だけ acquire を発行する。失敗は blocked にし、`retry` は失敗した stage だけを新 ID で再発行する。 |
| 3 | ○ | pending ID は intent 更新で不変、各 command/retry で `nextId` から新規発行する。不一致 ID の完了は state/effects とも不変である。 |
| 4 | ○ | 排他方針は純粋な親モデルにあり、実行の詳細は effects の受け手へ残した。 |
| 5 | ○ | `profile` は同一 state と空 effects を返す。子の局所状態はモデルに含めない。 |
| 6 | ○ | 下記の実行済み assertion は、intent の往復、停止・解放失敗、retry、stale completion、profile 独立、取得失敗をモデルの出力で確認する。 |

## 不明点・原因・一般化した修正規則

- 不明点: acquisition 完了後に intent が異なる場合、取得済み target を状態に保存する必要がある。
- 原因: acquisition 中の `desired` は最新 intent なので、開始時 target と同じ値ではなくなる。
- 一般化した修正規則: 実行中の対象は intent と別に保持し、完了時にはその実行対象と最新 intent を比較する。

## 裁量と再試行

取得失敗では intent を `null` に戻した。自動再取得や idle での retry は追加していない。retry は blocked の失敗 stage に限り、繰返し実行は 0 回である。

## Post-evaluation 整形

元の自己評価は変更していない。実測すると、同梱 `demo()` の失敗 assertion は release（ID 3）と acquire（ID 5）であり、stop 失敗（ID 2）の遷移 assertion は未実行だった。したがって E-6 の post-evaluation 判定は **partial** である。Issue は「停止失敗を検査済みと報告したこと」、Cause は「stop 成功から release 失敗へ進む経路だけを assertion したこと」。General Fix Rule は、既存の実行手段で遷移を assert し、実行した検査と未実行の確認を分け、実行結果に裏付けられた範囲だけを報告すること。

`oxfmt` で `e2.mjs` を整形した。アルゴリズムと同梱 assertion の内容は変更していない。
