## 未使用holdout D（dispatch前固定）

既存React/Queryフォームはフォームbindingが入力値とdraft revisionを保持する。明示saveはクリック時のrevisionと値をsnapshotとして既存use caseへ渡し、同時saveは1件に限定するが、保存中の入力編集は許可する。成功時はそのsnapshotのrevisionが保存済みになり、現在のdraftが先へ進んでいればdirtyを保持する。失敗時は保存済みrevisionを進めない。新しいsaveの進行中に古い成功・失敗の重複通知が来ても現在の進行を変えない。use caseが業務検証を行う。取消・自動再試行・Effect導入は求めない。責務メモとNode標準assertによる抽象実行モデルを作る。

1. [critical] 保存中の編集を保持し、古いsnapshotの保存成功で新しいdraftを保存済み扱いにしない。save commandの値とrevisionは後続編集から独立する。
2. [critical] 失敗で保存済みrevisionを進めず、古い成功・失敗は新saveの進行を変更しない。同時saveを二重起動しない。
3. フォームbindingの入力・revisionと既存Query実行を再利用し、モデルの各状態を模擬／本実装で追加／検証専用に区分する。
4. 業務検証はuse caseに残し、既存実行境界を使い、Effect移行や取消・自動再試行の仕組みを追加しない。
5. 初期状態からの通常save成功、保存中編集、失敗、古い通知を実行assertし、メモと一致する実行結果・未検証範囲を記録する。
6. saveのUI裁定を1つの名前付き所有者へ集め、形式チェック・表示整形はフォーム/Viewに残す。

判定は他課題と同じ。直前の平均から15点以上落ちた場合は過適合の疑いとして再設計する。Dも一度使えば以降はholdoutとして再利用しない。
