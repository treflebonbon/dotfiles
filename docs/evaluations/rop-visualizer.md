# rop-visualizer の設計と評価

2026-09-09。`ui-grill-with-docs` で設計し、`skill-creator` と `empirical-prompt-tuning` で実行評価した user-scoped private skill。

## 採用した振る舞い

- 入力は既存リポジトリのファイル・入口関数。必要なローカル呼出し先まで読む。
- 目的は実装理解とレビュー。成功・失敗・回復を縦向きの Mermaid フローチャートで示す。
- 図を上、選択した処理の説明・実コード抜粋を下に置く。補足は折りたたむ。
- 実現可能な名前付き経路を一つ選んで強調する。静的な説明であり、実行ログではない。
- Effect v3 の `A/E/R`、fallible `tap`、局所的な `catchTag` と外側の `mapError` を区別する。
- Rust の `?` の返却先、`From`、限定的な `or_else`、`map_err` をソースから確認する。
- 不明な外部実装は境界として残す。実装を読み取る処理に型解析器や対象プログラムの実行は持ち込まない。

[スキル本文](../../local-skills/rop-visualizer/SKILL.md)、[モデルと生成手順](../../local-skills/rop-visualizer/references/report-format.md)。

現在の既定は、表示方式の比較後にユーザーが選択した `flowchart TB`。詳細は末尾の「フローチャートの採用」を参照する。

初期評価では Mermaid の `block-beta` を選び、明示的な列で成功線を上・失敗線を下に配置した。`flowchart LR` の自動配置では上下と列揃えが安定しなかった。生成時は既存の Playwright CLI セッション内の一時タブに Mermaid 11.17.2 を読み込み、SVG を HTML へ内包する。閲覧時の外部依存はない。[Mermaid block diagrams](https://mermaid.js.org/syntax/block.html)、[Mermaid usage](https://mermaid.js.org/config/usage.html)。

## 固定した評価

[evals.json](../../local-skills/rop-visualizer/evals/evals.json) に3シナリオ・各6項目を保存した。各シナリオには critical な意味要件を一つ置いた。実行開始後にチェック項目や critical 指定を変更していない。この定義は当初の railway 指定を含む履歴であり、現在のフローチャート出力に対する比較評価結果ではない。

| シナリオ               | 狙い                                                                 |
| ---------------------- | -------------------------------------------------------------------- |
| Effect checkout        | typed error の迂回、OutOfStock 限定回復、fallible tap、R と E の分離 |
| Rust checkout          | 入れ子の `?`、From 変換、局所的な代替予約と代替自体の失敗            |
| 未使用例: Rust invoice | 早期 return と局所回復の範囲、外側の決済失敗、未知の外部実装         |

各実行者は履歴を引き継がない新規サブエージェント。最初の2ケースは各版でスキルあり・なしをそれぞれ1回実行し、実際の HTML を作成した。同時実行枠が3のため一部は空き枠を待って起動した。未知の外部実装を含むケースは最終版だけに渡した。基準作成用の fixture 修正はすべて初回実行前に完了し、SHA-256 を固定した。

初回の3出力、2回目のスキルなし2出力、未使用例は別の評価者が採点し、その他は実装側でソース・図・経路を照合した。自己申告の○をそのまま採用せず、親セッションでも DOM を操作した。

| --- | -------- | ------ | -------- | -------- | ------------------ |
| 1   | effect   | あり   | ○        | 5/6      | 2                  |
| 1   | effect   | なし   | ○        | 6/6      | 3                  |

成功判定は固定した critical 要件の充足だけを表す。達成項目とは区別する。すべてバイナリ採点で、時間・tool_uses・トークン数は全実行で未計測。

2回目のスキルなし出力は、説明文や同梱 Mermaid テキストが正しくても手書き SVG の矢印に未接続箇所があった。最終版は Mermaid 自体で図を生成し、連続するモデル経路を検査した。これらの少数例から一般的な成功率の差は推定しない。

主要な弱点は初回スキルありの Formatting（過大な図幅）、スキルなしの Execution（SVG と制御フローの不一致）。コマンドの引用・DOM を読む実行コンテキスト・共有ブラウザーの file 制限による再試行は、意味の誤読と分けて記録した。

## 改善内容と限界

初回はノードと同じ幅の空列、長い型名入りラベルにより、図の自然幅が Effect 4250.5px、Rust 5690.4px に広がった。1142px の表示領域では2段階しか見えず、Effect の「初期状態で全体経路を読める」は不合格とした。

2回目は空列を除き、短い動作ラベルと必要な段階への集約を指示した。図は Effect 1313.5px、Rust 1452.9px へ縮まった。文字を16pxから14pxまで縮小できる表示と合わせ、成功の流れを見渡せる。Rust の末尾失敗終端はデスクトップでも少し横スクロールが必要で、狭い画面では両方の図を横スクロールする。

初回の Effect critical 要件には採点の修正がある。最初の評価者は「通常成功でも独立した catchTag ノードを通ること」を必須と解釈したが、成功は pass-through であり、回復ハンドラだけを失敗側に描くモデルは正しい。固定した要件文を変更せず、実装の意味に照らして再監査した。

時間・tool_uses・トークン数の native metadata は取得できないため未計測とした。出力文字数や0で代用していない。各条件1実行であり、標準偏差は異なるシナリオ間の差で、同じタスクの反復分散ではない。人間の認知負荷低減やスキルの統計的な優位性は未検証。

反復は2版と未使用例までで resource cutoff とする。主要な誤読・接続・操作を実際の成果物で検査できた一方、残る読みやすさは人間のレビューが必要である。追加の同種エージェント実行だけで人間の理解を測れないため、厳密な速度・手数の収束を達成したとは報告しない。

## 初期評価時の再検証

fixtures は評価時のソースを byte-for-byte で保存した `.fixture` ファイルである。対象プロジェクトの入力データなので、この dotfiles 自身の TypeScript lint 規約で書き換えない。[frozen-manifest.json](../../local-skills/rop-visualizer/evals/frozen-manifest.json) で同一性を検証できる。再実行用の空ディレクトリに `inputs/` を作り、`.fixture` を外した名前でコピーして、そこをソースルートとして各 prompt を実行する。

```bash
bats tests/rop-visualizer.bats tests/local-skills.bats \
  tests/run_onchange_before_remove-orphan-claude-skills.bats
python3 tests/helpers/rop-renderer-contract.py \
  local-skills/rop-visualizer/scripts/render.py
```

関連 Bats は37件すべて成功した。renderer の6テストは実ソース抜粋、リポジトリ境界・行範囲、経路接続と終端、セル衝突、Mermaid の列と文字エスケープ、SVG の識別子と外部内容を検査する。実ブラウザーでは、ネットワーク遮断、ノードのキーボード選択、ソース開閉、全経路の強調辺数、リセット、390px 幅の本文を確認した。別の小さいレポートではポインタ操作と、ソースに含まれる `</script>` が要素として実行されないことも確認した。

Effect fixture は Effect 3.22.1 に対して TypeScript の strict typecheck を通した。Rust は rustc が環境にないためコンパイルしていない。未知の外部実装を含む invoice fixture は単独コンパイル用ではない。

実行出力と公式 review viewer は task worktree の `tmp/rop-visualizer-workspace/iteration-{1,2}/` に保存する。配布元は `local-skills/rop-visualizer/`。通常の受入・merge 後、live source の chezmoi apply で各ランタイムへ反映する。

公式 skill-creator viewer の静的生成物は、JSON 内の `</script>` が埋め込み script を閉じて表示を壊したため、生成済みファイルのデータを Unicode escape で保護した。同じ生成物で HTML を先に並べ、`sandbox="allow-scripts"` の iframe にプレビューする補正を加えた。共有 skill のソースは変更していない。比較集計では未計測の時間・トークン欄を非表示にし、未使用例をペア比較の平均から除外した。

同じモデルと Mermaid SVG に新しい CSS を適用した3例を `tmp/rop-visualizer-workspace/final-examples/` に生成した。1440px・390px幅で文字サイズと本文の横はみ出しを確認し、各例でノードのキーボード選択、ソース開閉、1経路の強調と解除を確認した。ネットワーク要求と JavaScript エラーはいずれも0件だった。エージェントによる意味の評価は再実行していない。

フックの例外は `impeccable hooks ignore-value` で[設定](../../.impeccable/config.json)に理由付きで保存し、個別ファイルとルールに限定した。

- `__CSS__` を後から埋め込むテンプレートと、`clamp()` を認識しない既存比較例の文字階層判定は誤検知。
- 比較例の広い字間は短い大文字ラベルだけに適用されている。破線用グラデーションは失敗線の凡例に使われている。
- 比較例の片側ボーダー、発光風の影、記録済みの文面は評価時の成果物を保存するための例外。
- 修正版3例の SVG 矢印ラベルは線を隠す背景で、カード用の CSS padding 判定は適用しない。実ブラウザーで SVG の背景と文字の座標を確認した。em-dash 判定は埋め込み Mermaid 構文に由来し、表示本文には0件だった。

プロジェクト全体のルール無効化やファイル全体の除外は追加していない。設定は chezmoi の配備対象に含まれないことを read-only に確認した。

## ユーザーレビュー後の重なり修正

ユーザーから線と文字が重なるとの指摘があり、表示画像と DOM 座標で再現した。前回の文字サイズ・操作確認では図の重なりを検出できていなかった。旧版の文字同士の重なりは Effect 15件、Rust 19件、未使用例18件。合格済みの操作チェックや静的スタイル検出だけでは、図の読みやすさを保証できない。

Mermaid の block 図は処理箱の位置を固定できる一方、短い箱間に長い辺ラベルが配置され、同じ段の遠い処理へ向かう直線が中間の処理箱を通過していた。採用版は次の変更を加えた。

- 図上の文字は処理名に絞り、すべての分岐条件と遷移先を選択した処理の下に表示する。遷移先ボタンから次の処理を選べる。
- Mermaid が生成した箱と辺の対応を維持し、列間に32pxの余白を配置する。隣接しない処理への辺は箱の外側を通る折れ線にし、迂回ごとに高さを分ける。
- 同じ成功段の連続処理は水平に接続し、回復・失敗の伝播も元のモデルの辺に対応する。経路選択はその同じ辺を強調する。

この経路調整は HTML 生成時の後処理であり、Mermaid 単体の自動配置機能ではない。同梱 `.mmd` は処理間の接続と条件コメントを保存するが、HTML 固有の線の経路調整は含まない。仕様の区別をスキルの生成手順にも追記した。

モデルと評価時の成果物は保存し、修正版は `tmp/rop-visualizer-workspace/layout-fixed/*/railway-final.html` に別名で生成した。スキル本文の確認項目も、実際の文字・辺・処理箱の座標と表示画像を確認する内容に更新した。固定した意味要件の採点や以前の実行記録は書き換えておらず、今回エージェント比較評価は再実行していない。

この時点の回帰確認では次を使った。現行 helper はフローチャートの識別子へ更新しているため、現在の再実行コマンドは末尾を参照する。出力先には当時の検査結果と PC・スマートフォン幅の画像を保持する。

## フローチャートの採用

ユーザーの「フローチャートでいい」という選択を受け、スキル本文・モデル説明・レンダラーを `flowchart TB` に統一した。`lane` は成功・失敗・範囲外という意味分類と色だけを表し、列位置の指定を廃止した。Mermaid の標準配置と接続線をそのまま使い、ノードと辺へ操作用の識別情報を付ける。以前の独自 SVG 配線処理は配布対象から外し、task worktree の比較資料へ移した。

長い条件は選択した処理の「ここからの分岐」に置く。処理の詳細・ソース抜粋・補足の開閉、遷移先ボタン、名前付き経路の強調を維持した。小さい図をデスクトップ幅いっぱいに拡大せず、狭い画面では文字を約14pxに保って図だけを横スクロールする。初期表示と画面幅変更時には、選択したノードが図の表示範囲に入るよう横位置を調整する。

新しい表示例は `tmp/rop-visualizer-workspace/flowchart-final/` 配下の3ケースの `report.html`。入力モデルの意味・接続・経路は、直前の表示修正版を引き継いでいる。現在の回帰確認は次で再実行できる。

```bash
python3 tests/helpers/rop-browser-check.py \
  tmp/rop-visualizer-workspace/flowchart-final/*/report.html \
  --session rop-flowchart --output tmp/rop-flowchart-verification-final
```

1440px・390px幅の全3例で、文字同士と線・文字の重なり、無関係な処理箱への線の侵入、端点の接続不一致は0件。デスクトップでは横スクロールなしで図全体を表示し、狭い画面でも開始ノードを表示できた。本文の横はみ出しと JavaScript エラーも0件だった。全37ノードのキーボード選択と該当するソース抜粋、44分岐の条件、17経路の強調辺・ノード、経路を維持したままのノード選択、分岐先ボタン、経路リセットをネットワーク遮断下で検証し、表示画像を確認した。

renderer の7テストと関連 Bats 37件が成功。列衝突と独自迂回配線の旧テストは、採用した仕様に合わせて、重複ノードの拒否と Mermaid の図形・線の形状を変えずに正しい識別子を結び付ける検査へ変更した。スキル構造の検証、JavaScript lint、書式検査も実施した。

デザイン検出で残った `em-dash-overuse` は、Mermaid ソース内の `E0@-->` などを数えた注意表示だった。件数が各図の接続数16・13・15と一致することを確認し、新しい3プレビューだけを対象に `impeccable hooks ignore-value` で理由付きの例外を保存した。重なりの検査は除外していない。

当初の railway 評価定義・採点・凍結出力を保持した。最初のフック対象4ファイルも SHA-256 が一致する。今回の変更はユーザーが選択した表示方式の実装とブラウザー検証であり、エージェント比較評価や人間の理解時間の測定を再実行したものではない。
