# Scenario B 実行メモ

## Deliverable

対象画面の既存の表示コンポーネントだけを変更する。

- 現在表示している合計値を、既存のフォーマッタに渡した結果で表示する。
- ヘルプ用トリガーとツールチップを同じ表示コンポーネントに追加する。開閉状態はそのコンポーネントの局所状態に置く。
- TanStack Query、共有 Context、compound components、既存の送信・業務ロジックはそのままにする。Mediator、reducer、Atom、Effect、接続専用コンポーネントは追加しない。

確認は、既存データで合計が既存フォーマッタの出力として表示されること、ヘルプを開閉できること、ツールチップの操作が送信可否・送信中状態・他の操作を変えないことを手動または既存の画面テストで確かめる。

## Requirement achievement

1. ○ TanStack Query とプロジェクト既存構成を維持し、Effect、Atom、MVP 移行を要求しない。
2. ○ 表示だけの変更を対象コンポーネントへ閉じ、Mediator、reducer、グローバル UI state を加えない。
3. ○ 複数の Context consumer を既存のまま許容し、単一 connector や転送専用の階層を要求しない。
4. ○ 既存フォーマッタを再利用し、ツールチップの開閉を局所状態に置く。開閉は他の操作に影響しないため Passive View の責務である。
5. ○ 業務規則と送信ロジックを移動・書換えしない。
6. ○ フォーマット表示とツールチップ開閉、ならびに送信等へ影響しないことだけを確認対象にする。

## Unclear points

- **Originating phase: Understanding**
  - **Issue:** 対象コンポーネント名、既存フォーマッタの import 元、既存テストの所在は指定されていない。
  - **Cause:** Scenario は構成と要求を固定しているが、具体的なコードベースを提示していない。
  - **General Fix Rule:** 実装時は対象画面の合計表示の呼び出し元とフォーマッタ利用箇所を確認してから、同じコンポーネント内に変更を限定する。

## Discretionary fill-ins

- 通常の適用判断として、ツールチップは送信や他操作に影響しないため、表示コンポーネントの局所状態で十分とした。
- これは指示の曖昧さによる補完ではない。具体的な識別子がないため、Deliverable では特定のコンポーネント名やテスト名を仮定していない。
