# R3-B: 既存 Query UI の表示保守メモ

## Deliverable

既存の React 画面で、表示済みの合計値を既存 formatter で整形し、合計値の説明用ツールチップを追加する。

- 合計値を描画する既存 View で既存 formatter を呼び、整形済みの文字列を表示する。
- 同じ View（または既存の局所的なツールチップ部品）に開閉状態を置く。開閉は表示だけを変え、送信や他の操作には通知しない。
- 既存 TanStack Query、共有 Context、compound components、送信・業務ロジックの責務配置はそのまま使う。

確認は、取得済みの合計値が既存 formatter の出力で表示されること、ツールチップが開閉できること、開閉後も送信状態・Query の取得状態・他の Context consumer に変化がないことを画面または既存のコンポーネントテストで確認する。

## 固定要件の達成

| 要件 | 判定 | 理由 |
| --- | --- | --- |
| 1. Query／プロジェクト設計を維持し、Effect／Atom／MVP 移行を要求しない | ○ | 既存の TanStack Query と画面構成を利用し、表示整形と局所 UI だけを加える。 |
| 2. Mediator、reducer、グローバル UI state を加えず局所化する | ○ | ツールチップは送信・取消・進行を左右しない表示状態のため、局所 state で足りる。 |
| 3. 複数 Context consumer と既存の接続構造を維持する | ○ | consumer、connector、pass-through hierarchy の統合や追加を行わない。 |
| 4. 既存 formatter を使い、ツールチップ state を局所に保つ | ○ | 新規の整形規則を作らず、既存 formatter の出力を表示に使う。 |
| 5. 無関係な業務／送信ロジックを移設・書換えしない | ○ | 対象は合計表示と説明の開閉だけであり、送信フローには触れない。 |
| 6. 整形とツールチップに見合う振る舞い確認を行う | ○ | formatter の表示結果、開閉、開閉による送信・Query 状態への非干渉を確認する。 |

## 裁量で補った点

「既存 formatter」と「既存の局所的なツールチップ部品」の具体名・所在は、変更メモの前提に含まれていない。そのため、実装時は合計を現在描画している View から既存 formatter を参照し、既存の tooltip 部品があればそれを使う、とした。これはアプリケーション方針（既存アーキテクチャを維持する）に従う実装上の選択であり、指示の曖昧さではない。

ツールチップの具体的な起動方法（クリック、hover、focus）は指定されていない。アクセシブルな既存部品の標準挙動を維持する。これは UI 詳細の未指定であり、MVP／Mediator の責務境界に関する指示の曖昧さではない。
