# R4-B: Scenario B change memo

## Deliverable

### 変更

- 既存の合計表示箇所で、取得済みの合計値を既存フォーマッタに通して表示する。
- その表示の近くにヘルプ用ツールチップを追加する。開閉を制御する必要がある場合だけ、その表示コンポーネント内の局所状態で保持する。既存ツールチップが非制御なら、その内蔵状態を使う。

### 所有を維持する箇所

- TanStack Query は取得・キャッシュ・再検証を引き続き所有する。
- 共有 Context と複数の compound component は、そのまま同じ表示データを読む。単一 connector や転送専用階層は追加しない。
- 合計の整形とツールチップの開閉は表示コンポーネントの局所責務に留める。
- 既存の送信・業務規則・送信状態の所有者は変更しない。Mediator、reducer、Atom、Effect、グローバル UI 状態は追加しない。

### 確認

- 代表的な取得済み合計が既存フォーマッタの表記で表示されることを確認する。
- ヘルプを開け、閉じられ、開閉中も合計表示が維持されることを確認する。
- ツールチップの開閉で送信操作・送信可否・Query の取得状態が変化しないことを確認する。

## 固定要件の達成

| # | 判定 | 理由 |
| --- | --- | --- |
| 1 | ○ | 既存の TanStack Query とプロジェクト構成を保持し、Effect・Atom・MVP 移行を求めない。 |
| 2 | ○ | 表示専用変更を表示コンポーネントに限定し、Mediator、reducer、グローバル UI 状態を追加しない。 |
| 3 | ○ | 複数の Context consumer を維持し、単一 connector や pass-through 階層を要求しない。 |
| 4 | ○ | 合計には既存フォーマッタを使い、ツールチップ状態は局所に保つ。 |
| 5 | ○ | 業務規則と送信ロジックを移動・書換えしない。 |
| 6 | ○ | 合計の整形、ツールチップの開閉、送信・取得状態への非干渉を確認する。 |
