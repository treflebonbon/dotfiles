# Holdout L

## Deliverable

### 責務マップ

| 所有者 | 責務 |
| --- | --- |
| 編集フォーム（Passive View） | 下書き値と形式チェックを保持し、`dirty` を編集画面の UI 所有者へ通知する。入力・表示・局所的な形式エラー表示だけを扱う。 |
| 編集画面の UI 所有者（Mediator） | ナビゲーション要求、破棄確認、確定、却下を唯一裁定する。`編集継続`、`破棄確認中(最新の遷移先)` を管理し、フォームの `dirty` を参照する。 |
| 破棄確認ダイアログ（Passive View） | UI 所有者から表示状態と最新の遷移先を受け、確定・却下を通知する。下書き破棄やナビゲーションを自ら行わない。 |
| ナビゲーション View | 遷移要求を UI 所有者へ送る。dirty 判定、ダイアログ表示、下書き破棄を自ら決めない。 |
| ヘルプパネル | 独立した表示フローとして局所状態を持つ。編集画面の UI 所有者には接続しない。 |
| フォームの既存モデル | 下書きの破棄操作と、形式チェックを含むフォーム状態を所有する。UI 所有者はそのモデルを複製せず、破棄を裁定した時だけ既存の破棄操作を依頼する。 |

ナビゲーションに業務判断はない。UI 所有者が扱うのは、dirty な下書きを残すか破棄するかという UI 遷移だけである。保存、通信、Effect の実行、Fiber の中断、scheduler、非同期状態は導入しない。

### 遷移メモ

| 前状態 | イベント | 後状態 | 効果 |
| --- | --- | --- | --- |
| 編集継続 | 遷移要求 `D`、`dirty = false` | 編集画面外 | `D` へ一度だけ遷移する。 |
| 編集継続 | 遷移要求 `D`、`dirty = true` | 破棄確認中(`D`) | ダイアログを表示する。保存・通信は行わない。 |
| 破棄確認中(`P`) | 遷移要求 `D` | 破棄確認中(`D`) | 待機先を常に最新の `D` に置換する。`A → B → A` では pending を最後の `A` に更新する。 |
| 破棄確認中(`P`) | 確定 | 編集画面外 | フォームの既存の下書き破棄を一度だけ依頼し、現在の pending `P` へ一度だけ遷移する。 |
| 破棄確認中(`P`) | 却下 | 編集継続 | pending を消去し、その場に留まる。 |
| 編集継続 | 却下後の遷移要求 `D`、`dirty = true` | 破棄確認中(`D`) | 新しい確認を開始し、古い pending を再利用しない。 |

`P` は比較によって更新を省略しない。元の遷移先へ戻る要求も、最後に受けた利用者意図として pending に書き込む。確定時だけフォームの破棄と遷移を採用し、却下時にはどちらも実行しない。

### 具体的な確認

| 確認 | 操作 | 期待結果 |
| --- | --- | --- |
| 確定 | dirty な編集画面で `A` を要求し、確認で確定する。 | 下書き破棄は一度、`A` への遷移は一度。保存・ネットワーク呼出はない。 |
| 却下後の新規要求 | dirty な編集画面で `A` を要求して却下し、次に `B` を要求する。 | `A` は破棄され、画面は編集継続のまま。次の確認は pending `B` で開く。 |
| 元の遷移先へ戻る反復要求 | dirty な編集画面で `A`、`B`、`A` の順に要求して確定する。 | ダイアログは開いたまま pending が最後の `A` になり、下書き破棄と `A` への遷移が各一度だけ行われる。 |
| フォーム責務 | dirty と形式エラーを変化させ、遷移要求を送る。 | UI 所有者は dirty 信号だけを参照し、下書き値・形式ルール・エラー状態のコピーを持たない。 |
| ヘルプの独立性 | ヘルプパネルを開閉し、編集画面で確認ダイアログを開く。 | ヘルプの局所表示だけが変わり、pending、ダイアログ、下書き、遷移には影響しない。 |
| 不在確認 | 上の全シナリオを追う。 | 保存、リモート呼出、通信中断、Fiber、scheduler、ミラーした非同期状態を必要とする遷移がない。 |

## 裁量による補完

- 同一遷移先の連続要求も pending を更新する。利用者意図の最新性を保ち、比較による例外規則を増やさないためである。
- `dirty = false` の遷移は確認を開かず、通常の一回の遷移として扱う。確認フローの対象が未保存の変更であるためである。
