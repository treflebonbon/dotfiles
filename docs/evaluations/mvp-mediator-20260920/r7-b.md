# Scenario B 変更メモ

## Deliverable

既存の TanStack Query 画面で、表示済み合計値に既存フォーマッタを適用し、同じ表示コンポーネントにヘルプ用ツールチップを追加する。ツールチップの開閉はその View の局所状態に留め、Query、共有 Context、送信、業務規則の所有者は変更しない。

## 責務と変更内容

| 対象 | 内容 |
| --- | --- |
| 合計表示 View | 取得済みの合計値を既存フォーマッタへ渡して描画する。ツールチップの開閉だけを局所状態で扱い、利用者操作を既存のツールチップ UI へ渡す。 |
| TanStack Query | 取得、キャッシュ、再検証を既存どおり所有する。 |
| 共有 Context と compound components | 複数 consumer の読取りを既存どおり許可する。単一 connector や中継コンポーネントは追加しない。 |
| 既存の送信・業務処理 | 既存の所有者に留める。表示整形とツールチップは送信可否、取消、進行状態を変更しない。 |

## 確認項目の達成

1. ○ Query とプロジェクト構成を維持する。Effect、Atom、MVP 移行は表示専用変更に必要ない。
2. ○ 変更は合計表示 View に局在する。Mediator、reducer、グローバル UI 状態を追加しない。
3. ○ 既存の複数 Context consumer を維持する。単一 connector や pass-through 階層は要求しない。
4. ○ 合計表示は既存フォーマッタを再利用し、ツールチップの開閉だけを局所状態に置く。
5. ○ 業務規則、送信、Query の取得・再検証のロジックを移動・書換えしない。
6. ○ 合計値が既存フォーマッタの出力で表示されること、ツールチップを開閉できること、開閉で送信状態や他の操作が変化しないことを確認する。

## 検証

既存の画面確認または既存テストの範囲で、次を確認する。

1. Query が返す合計値について、表示文字列が既存フォーマッタの出力と一致する。
2. ツールチップを開くと説明が表示され、閉じると説明だけが消える。
3. 開閉の前後で Query のデータ、共有 Context の他 consumer、送信中表示と送信操作が変化しない。

## 裁量補完

- ツールチップは既存部品が提供する開閉操作とアクセシビリティ挙動を使う。新しい独自実装は追加しない。
- フォーマット失敗時の表示方針は既存フォーマッタの振る舞いを維持する。
