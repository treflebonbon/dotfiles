## 実装Contract

設計対話Q1〜Q4で次を確定した。

1. 改善対象はskill単体。実装・抽象モデルを作る前に、既存の状態表へ目的・所有者・区分・本実装の取得元を記入する。不明なら未確認と確認対象を示す。実装後に全保持フィールドへ合わせて更新する。
2. 検証報告の本体は「ケース／操作・観測時点／照合する値と期待値／assertionの所在／実行結果」の表とする。状態と効果はそれぞれの根拠を示し、検証済みの説明を根拠の範囲へ限定する。
3. 要件上必要な検査の不足は追加・再実行で埋め、それ以外の未検証事項も明記する。提案のみなら具体的なケースと期待値を示し、assertion・実行結果は未実装／未実行とする。
4. 既存の責務分担・適用範囲・ケース分離・純粋性・導出表示の要件を維持する。新しい報告生成プログラムや実行者分離は導入しない。
5. 公開CLIのinit/prepareで新本文とv2〜v6契約を固定・配布するための版登録だけを更新し、評価手順・採点・runtimeを維持する。

検証境界は既存の合意済み公開CLI fixture。専用Batsで新版固定・配布のred→green、型確認、全体テスト、Standards/Specレビューを行う。本文の行動改善はfixtureの検証対象ではなく、別の明示的な実測評価に残す。
